الفصل الأول: نظرة عامة، مبررات وأهداف المشروع

1.1 مشكلة الدراسة ومبرراتها

تتميز محافظة الأحساء باتساع مساحتها وتباعد مراكزها التعليمية والتجارية (مجمع الكلية التقنية، جامعة الملك فيصل، محطة قطار سار، سوق القيصرية، العثيم مول، جبل القارة، ومطار الأحساء). وكان يعاني الركاب والطلاب من عدم دقة مواعيد الحافلات، وعدم توفر وسيلة لحجز المقعد مسبقاً، وصعوبة معرفة أقرب محطة حافلات لهم في اللحظة الراهنة، مع غياب تتبع حي لحركة الحافلة.

1.2 الحل المبتكر والأهداف

تم تطوير تطبيق ويب تقدمي (PWA) فائق السرعة والأمان، يُمكّن الراكب من: (1) معرفة أقرب محطة حافلات بالـ GPS وحساب مسافة السير بدقة، (2) حجز المقعد برقم مقعد مخصص وسقف أسعار لا يتجاوز 8 ر.س، (3) تتبع حركة الحافلة اللحظية وسرعتها ووقت وصولها التقديري، (4) مركز مساعدة ودعم فني متكامل للشكاوى والاستفسارات.

1. الركاب والطلاب

حجز المقاعد الفوري، معرفة أقرب محطة، التتبع الراداري، وتذاكر رقمية ذكية.

2. السائقون المعتمدون

تسجيل بيانات الحافلة، إطلاق الرحلات، بث الإحداثيات الحية، وتأكيد صعود الركاب.

3. إدارة العمليات

اعتماد السائقين، مراقبة الإيرادات، تسجيل اسم المدير، وإصدار الإعلانات وتذاكر الدعم.

الفصل الرابع: مخطط آلية عمل وهندسة النظام (System Mechanism & Architecture)

الشكل 3: معمارية وتدفق البيانات

يوضح المخطط الهيكلي التالي آلية عمل التطبيق من اللحظة التي يفتح فيها الراكب التطبيق وحتى وصوله لوجهته:

1. طبقة الأجهزة والمستخدمين (Presentation & Client Layer)
تطبيق الراكب (Passenger UI) حجز المقاعد · تحديد أقرب محطة بالـ GPS · تتبع الحافلة
تطبيق السائق (Driver UI) بث الموقع الحي للحافلة · إدارة الركاب وصعودهم
لوحة الإدارة (Admin UI) اعتماد السائقين · التسعيرة والمسارات · الرد على التذاكر
▼ بروتوكولات التزامن اللحظي JSON Over REST API ▼
2. طبقة الخوارزميات والمعالجة الذكية (Processing Engine Layer)
خوارزمية حساب المسافة (Haversine Distance Formula)

حساب المسافة الجغرافية الدقيقة بين إحداثيات الراكب ومحطات الأحساء لاكتشاف أقرب محطة سيراً ووقت الوصول بالدقائق.

محرك التتبع والمحاكاة اللحظية (Bus Movement Engine)

تحريك الحافلات بسلاسة كل ثانيتين على طول مسار الرحلة، وتحديث إحداثيات الرادار وحساب المسافة وسرعة الحافلة (~42 كم/س).

▼ مزامنة السجلات وقاعدة البيانات المشتركة ▼
3. طبقة الخادم وقاعدة البيانات (Server & Database Layer)
خادم Express Node.js السحابي
مسار /api/transit/state المسؤول عن مزامنة التذاكر والرحلات عبر الهواتف المختلفة فورياً.
تخزين الحالات وقاعدة البيانات
ملف transit-db.json مع دعم التخزين المحلي في المتصفح لضمان العمل Offline.
آلية تسلسل العمليات خطوة بخطوة (Operational Sequence):
  1. إطلاق الرحلة: يقوم السائق المعتمد باختيار مسار الحافلة وبدء الرحلة لبث إحداثياتها كل ثانيتين.
  2. تحديد الموقع: يفتح الراكب التطبيق ويكتشف نظامه أقرب محطة له بالأحساء عبر Geolocation API ومسافة السير.
  3. حجز المقعد: يختار الراكب وجهته ويحجز مقعده برقم مقعد مخصص فوراً دون انتظار.
  4. التتبع الراداري: يضغط الراكب على "تتبع الباص" فيشاهد حركة الحافلة المباشرة وسرعتها وتوقيت وصولها.
  5. الصعود والإتمام: عند وصول الحافلة للمحطة، يؤكد السائق صعود الراكب (Boarded) لإتمام الرحلة.
