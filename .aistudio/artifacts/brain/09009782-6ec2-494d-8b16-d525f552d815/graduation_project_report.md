# وثيقة مشروع التخرج الأكاديمي
## منظومة حافلات الأحساء الذكية للنقل العام (Al-Ahsa Smart Transit Network)

* **المملكة العربية السعودية** — وزارة التعليم / المؤسسة العامة للتدريب التقني والمهني
* **الكلية التقنية ومجمع الكليات بالأحساء** — قسم تقنية الحاسب وهندسة البرمجيات
* **إعداد الطالب:** طالب مشروع التخرج | **إشراف:** سعادة الأستاذ / المشرف الأكاديمي
* **العام الأكاديمي:** 1447 - 1448 هـ / 2026 م

---

## 1. الملخص التنفيذي للمشروع (Executive Summary)
مشروع **منظومة حافلات الأحساء الذكية** هو حل تقني رقمي متكامل يهدف إلى تحديث وتطوير قطاع النقل الجماعي الترددي في واحة الأحساء (الهفوف، المبرز، جامعة الملك فيصل، مجمع الكلية التقنية، محطة قطار سار، والقرى الشرقية).

يوفر النظام تطبيقاً ويب تقدمياً (PWA) فائق السرعة يعمل عبر الهواتف الذكية والأجهزة اللوحية والمكتبية، ويتيح للركاب حجز مقاعدهم مباشرة، واكتشاف أقرب محطة حافلات لموقعهم الفعلي عبر الـ GPS، وتتبع حركة الحافلات اللحظية ورادار السرعة ووقت الوصول التقديري (ETA)، مع توفير لوحة تحكم للسائقين لبث الإحداثيات وإدارة صعود الركاب، ولوحة إدارة مركزية للمراقبة والاعتماد، ونظام متكامل لتذاكر الدعم الفني وخدمة العملاء.

---

## 2. المشكلة والحل المقترح (Problem Statement & Solution)

### 2.1 مشكلة الدراسة:
1. اتساع محافظة الأحساء وتباعد المراكز الحيوية (الجامعة، الكلية، محطة القطار، المطار، الأسواق).
2. عدم معرفة الركاب بمواعيد وأماكن الحافلات بدقة واضطرارهم للانتظار في الأجواء الحارة.
3. غياب نظام حجز مقاعد شفاف ومؤكد مسبقاً.
4. عدم معرفة الراكب بأقرب محطة حافلات لموقعه الحالي أثناء وجوده في الشارع.
5. غياب منصة موحدة تجمع الركاب والسائقين والإدارة وتوفر خدمة عملاء وتذاكر دعم فني.

### 2.2 الحل التقني المقترح:
منصة رقمية موحدة تعتمد على تقنيات الويب الحديثة، تدمج خرائط الأحساء التفاعلية وخوارزميات تحديد الموقع الجغرافي (Geolocation API) وحساب المسافات الدائرية (Haversine Formula)، وتتبع الحافلات المتحركة كل ثانيتين مع الحفاظ على سقف أسعار رمزي يتراوح بين 4 إلى 8 ريال كحد أقصى.

## 3. الفئات المستفيدة وأدوار النظام (System Roles & Stakeholders)

1. **الركاب والطلاب (Passengers):**
   - استعراض جدول الرحلات المتاحة في محافظة الأحساء.
   - كشف أقرب محطة حافلات لموقع المستخدم الفعلي عبر GPS مع حساب مسافة السير والوقت المقدر.
   - حجز مقعد رقمي برقم مقعد مخصص فوراً.
   - رادار تتبع حركة الحافلة المباشر، سرعتها ومسافتها ووقت وصولها.
   - إلغاء الحجز قبل انطلاق الرحلة لإتاحة المقعد لراكب آخر.
   - مركز مساعدة ذكي يشمل الأسئلة الشائعة ونظام تذاكر الشكاوى والاستفسارات.

2. **السائقون المعتمدون (Drivers):**
   - تسجيل بيانات السائق ورقم اللوحة وموديل الحافلة وسعتها.
   - إطلاق الرحلات على المسارات المعتمدة لبث الإحداثيات كل ثانيتين.
   - متابعة قائمة الركاب الحاجزين وتأكيد صعودهم (Boarding Confirmation).
   - خريطة تفاعلية توضح نقاط نزول الركاب على طول المسار.

3. **إدارة العمليات المركزية (Central Administration):**
   - مراجعة واعتماد طلبات السائقين الجدد والحافلات.
   - تسجيل وتعديل اسم مسؤول الإدارة المعتمد.
   - جدولة الرحلات وتحديد المحطات والمسارات والتسعيرة.
   - نشر الإعلانات العامة والتنبيهات الموجهة لكافة مستخدمي النظام.
   - الرد على تذاكر الدعم الفني وحل شكاوى الركاب وإغلاق التذاكر.

## 5. آلية عمل وهندسة النظام (System Mechanism & Flow)

### 5.1 المعمارية متعددة الطبقات (الشكل 3):
```text
 ┌───────────────────────────────────────────────────────────────────────┐
 │       الطبقة الأولى: واجهات المستخدمين والأجهزة (Client Layer)         │
 │   [تطبيق الراكب (PWA)]      [لوحة السائق والبث]    [لوحة تحكم الإدارة]│
 └──────────────────────────────────┬────────────────────────────────────┘
                                    │ طلبات REST API / JSON Over HTTP
                                    ▼
 ┌───────────────────────────────────────────────────────────────────────┐
 │         الطبقة الثانية: محرك المعالجة والخوارزميات (Engine Layer)     │
 │  * خوارزمية Haversine: لحساب أقرب محطة حافلات للراكب سيراً بالـ GPS    │
 │  * محرك Bus Movement Engine: محاكاة وتحديث إحداثيات وسرعة الحافلة     │
 │  * خوارزمية ETA Calculator: تقدير وقت الوصول والمسافة المتبقية         │
 └──────────────────────────────────┬────────────────────────────────────┘
                                    │ مزامنة الحالات اللحظية
                                    ▼
 ┌───────────────────────────────────────────────────────────────────────┐
 │          الطبقة الثالثة: الخادم وقاعدة البيانات (Server & DB Layer)   │
 │  * خادم Express Node.js عبر مسار المزامنة /api/transit/state          │
 │  * قاعدة البيانات المشتركة transit-db.json مع التخزين المحلي الكاش    │
 └───────────────────────────────────────────────────────────────────────┘
```

### 5.2 تسلسل العمليات خطوة بخطوة (Operational Sequence):
1. **إطلاق الرحلة:** يقوم السائق المعتمد باختيار مسار الحافلة (مثلاً مسار الجامعة والكلية 101) ويضغط "بدء الرحلة".
2. **بث الإحداثيات:** يبدأ السيرفر ومحرك الحركة ببث إحداثيات الحافلة اللحظية.
3. **تحديد موقع الراكب:** يفتح الراكب هاتفه، فيحدد التطبيق موقعه بالـ GPS ويخبره: "أنت على بعد 350 متراً من محطة الكلية التقنية (4 دقائق سيراً)".
4. **حجز المقعد:** يختار الراكب الرحلة المناسبة ويحجز المقعد برقم مقعد مخصص فوراً.
5. **التتبع الراداري:** يضغط الراكب على "تتبع حركة الباص"، فيظهر له رادار مباشر يوضح اقتراب الحافلة منه وسرعتها (42 كم/س) ووقت وصولها.
6. **الصعود والإتمام:** عند ركوب الحافلة، يؤكد السائق صعود الراكب (Boarded) لاكتمال دورة الرحلة بنجاح.

## 6. المواصفات الفنية والتقنيات المستخدمة (Technical Stack)

| المجال | التقنية المستخدمة | الوظيفة |
| :--- | :--- | :--- |
| **واجهة المستخدم (Frontend)** | React 18, TypeScript, Tailwind CSS, Lucide Icons | بناء واجهات سريعة متجاوبة مع الهواتف الذكية ودعم كامل للغة العربية (RTL) |
| **خادم التطبيق (Backend)** | Node.js, Express.js, REST API, TSX Execution Runtime | معالجة الطلبات ومزامنة الحجوزات بين الأجهزة المختلفة فوراً |
| **الموقع الجغرافي والخرائط** | W3C Geolocation API, SVG Vector Mapping Engine | تحديد موقع المستخدم ورسم خريطة الأحساء ومساراتها |
| **الحسابات الرياضية** | Haversine Great-Circle Distance Algorithm | حساب المسافة الدائرية بالأمتار بين إحداثيات الراكب والمحطات |
| **التوافقية والأجهزة** | Progressive Web App (PWA), Service Worker Caching | إتاحة التثبيت والعمل دون انقطاع عبر مختلف أنواع الأجهزة |
| **الأمان وإدارة الوصول** | Role-Based Access Control (RBAC: Passenger / Driver / Admin) | تأمين الصلاحيات والفصل التام بين الركاب والسائقين والإدارة |

## 7. الخاتمة والتوصيات المستقبلية (Conclusion & Future Work)
حقق المشروع كافة أهدافه بنجاح، وقدم نموذجاً عملياً قابلاً للتطبيق الميداني الفوري لخدمة أهالي وطلاب محافظة الأحساء تماشياً مع رؤية المملكة 2030 في التحول الرقمي وجودة الحياة.

**التوصيات المستقبلية:**
1. ربط بوابات الدفع الإلكتروني الوطنية (مدى، Apple Pay).
2. إرسال إشعارات لحظية عبر الرسائل القصيرة (SMS) أو Push Notifications عند اقتراب الحافلة من المحطة بمسافة 500 متر.
3. تزويد الحافلات بأجهزة قراءة باركود (QR Code Scanners) لصعود الركاب ذاتياً.
